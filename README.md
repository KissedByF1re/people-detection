# Система детекции людей на видео

В данном репозитории будет представлен прототип системы для детекции людей на видео. Система умеет точно и быстро распознавать людей в различных условиях освещения и погоды.

Ссылка на инференс - [Real-time people detection](https://huggingface.co/spaces/ekabaruh/real-time-people-detection)

## 📦 Описание и подготовка датасета

Для обучения модели использовался датасет с изображениями людей из [Human Detection Dataset (Kaggle)](https://www.kaggle.com/datasets/constantinwerner/human-detection-dataset), содержащий 559 реальных изображений.

### 🔄 Псевдоразметка

Так как исходный датасет не содержал аннотаций, была применена **псевдоразметка** с помощью модели `YOLOv8n`, предобученной на COCO. Из полученных `.txt`-файлов оставлялись только метки **класса 0 (человек)**. Остальные классы отбрасывались, а пустые файлы — сохранялись как фоны.

### 🧪 Аугментация

Для увеличения объема и разнообразия обучающей выборки была применена **offline-аугментация**, доведя общее количество изображений до ~5000. Использовались следующие методы (библиотека `albumentations`):

- `RandomBrightnessContrast` — имитация различного освещения
- `MotionBlur`, `GaussianBlur` — размытие, как при движении или фокусе
- `CLAHE`, `Sharpen`, `Emboss` — усиление деталей
- `RandomFog`, `RandomRain` — погодные условия
- `CoarseDropout` — имитация частичных перекрытий
- `HorizontalFlip`, `Rotate` — изменение перспективы

### 🧹 Чистка и подготовка

- Все `.txt`-разметки были очищены: оставлены только строки с классом `0`.
- Пустые `.txt` файлы не удалялись, а интерпретировались как "background only".
- Финальный датасет был разделён на:
  - `train` (80%)
  - `val` (10%)
  - `test` (10%)

### 📁 Структура итогового датасета

```
final_dataset/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
```

Такой подход обеспечил достаточное разнообразие и устойчивость модели к реальным условиям (тени, погода, частичные перекрытия и т.д.).

## Масштабируемость и оптимизация

### Тестирование производительности

Мы провели комплексное тестирование производительности различных моделей YOLOv8 (nano, small, medium) и наших кастомных моделей YOLO11 с ограничением в 8 CPU. Тестирование проводилось на трех различных видеосценариях:
- Видео с одним человеком (one-by-one-person-detection.mp4)
- Видео в магазине (store-aisle-detection.mp4)
- Видео с несколькими людьми (people-detection.mp4)

Основные метрики:
- Задержка (latency)
- Кадры в секунду (FPS)
- Потребление памяти
- Использование CPU
- Точность детекции

### Результаты производительности

#### Средний FPS по моделям:
- YOLOv8n: 5.3 FPS (самая быстрая стандартная модель)
- YOLOv8s: 4.3 FPS
- YOLOv8m: 3.3 FPS (самая медленная модель)
- YOLO11n: 5.5 FPS (самая быстрая модель среди всех)
- YOLO11s: 5.1 FPS
- YOLO11m: 3.9 FPS

#### Потребление памяти:
- YOLOv8n: ~437 МБ (самое низкое потребление памяти)
- YOLOv8s: ~522 МБ
- YOLOv8m: ~710 МБ
- YOLO11n: ~810 МБ
- YOLO11s: ~872 МБ
- YOLO11m: ~861 МБ (наши кастомные модели требуют больше памяти)

#### Использование CPU:
- Все модели эффективно работают в пределах ограничения в 8 CPU
- Измеренные значения показывают низкое относительное потребление CPU, однако фактическая нагрузка на процессор при обработке видео в реальном времени выше и составляет примерно 20-30% для легких моделей (nano) и 40-60% для средних и тяжелых моделей

### Удовлетворение техническим ограничениям

Система удовлетворяет заданным ограничениям:
1. **Ограничение в 8 CPU**: Все модели эффективно работают с ограничением в 8 CPU, демонстрируя низкое использование процессора.
2. **Производительность в реальном времени**: Легкие модели (YOLOv8n, YOLO11n) обеспечивают около 5 FPS, что достаточно для многих сценариев наблюдения в реальном времени.
3. **Баланс между скоростью и точностью**: Наши кастомные модели (особенно YOLO11n) обеспечивают лучший баланс между скоростью работы и точностью детекции.

### Возможности оптимизации

Для оптимизации системы и повышения производительности в реальном времени рекомендуются следующие подходы:

1. **Выбор оптимальной модели в зависимости от сценария**:
   - Для систем мониторинга с низкими требованиями к задержке: YOLO11n или YOLOv8n
   - Для более критичных сценариев с требованиями к высокой точности: YOLO11s или YOLOv8s
   - Для офлайн-анализа с максимальной точностью: YOLO11m или YOLOv8m

2. **Оптимизация инференса**:
   - Использование TensorRT для ускорения на NVIDIA GPU
   - Квантизация моделей (int8) для уменьшения потребления памяти и ускорения инференса
   - Оптимизация предобработки изображений (уменьшение размера входного изображения)

3. **Сценарии масштабирования**:
   - Горизонтальное масштабирование: распределение обработки видеопотоков между несколькими серверами
   - Вертикальное масштабирование: добавление GPU для параллельной обработки потоков
   - Краевые вычисления: размещение легких моделей на краевых устройствах для предварительной фильтрации

4. **Оптимизация для конкретных сценариев**:
   - Системы охраны периметра: выделение зон интереса для снижения нагрузки
   - Подсчет людей: специализированные облегченные модели только для подсчета
   - Анализ поведения: комбинирование детекции с легкими моделями трекинга

Наше тестирование показывает, что система способна работать в режиме реального времени с ограниченными ресурсами, а дальнейшая оптимизация может значительно улучшить производительность для конкретных сценариев применения.
